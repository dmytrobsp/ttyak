# ttyak 0.12.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship milestone 0.12.2: Windows hardening, help matching the code (#31), VIPs as Slack does them (#32),
notification leftovers (#15, #17), `publish.sh --wiki-dir` (#33), the 0.11.0 leftovers (#28), then the release.

**Architecture:** Small, independent fixes in the existing modules (slack-core `session.rs`; ttyak `status_file.rs`,
`login_import.rs`, `uninstall.rs`, `update.rs`, `tui/notify.rs`, `tui/attention.rs`, `tui/others.rs`, `tui/state.rs`,
`tui/prefs*.rs`, `tui/help.rs`, `tui/commands.rs`, `tui/huddle_view.rs`, `keymap.rs`, `ctl.rs`; `tools/wiki/publish.sh`),
each with its tests; the wiki pages under `docs/wiki/` follow the behaviour they describe.

**Tech Stack:** Rust (tokio, windows-sys 0.61 already in Cargo.lock), Python 3 unittest + bash for `tools/wiki`.

**Spec:** `docs/superpowers/specs/2026-10-26-0.12.2-design.md` — read it first; it holds every decision and its why.

## Global Constraints

- The Bash tool runs bash, not fish: `NAME=value`; `set -euo pipefail` first; never a recursive chmod/chown/rm/mv/cp or
  `find -delete` on a path built from a variable (literal path or `${VAR:?}` + a check). Put these rules in every
  subagent prompt.
- TDD for code: show the RED. The whole `cargo test` before every Rust commit; never commit on red. No `cargo fmt`;
  never build `target/release`; `cargo build` before any live run. Windows code must also compile:
  `cargo build --target x86_64-pc-windows-gnu` and `cargo test --no-run --target x86_64-pc-windows-gnu` (mingw is
  installed; CI cross-builds the same way).
- One commit per task (a second for its docs is fine), explicit paths, never chained with a scripted edit; never
  `git add -f .superpowers`; trailer `Co-Authored-By: Claude <model> <noreply@anthropic.com>`. Commits that fix an
  issue say `Fixes #N`. Public wording: the Windows hardening commits say "hardening", no exploit description.
- Implementers never push, tag, publish the wiki, file issues or dispatch subagents.
- Live checks: never the `test` profile (the user's work workspace) — `--profile default` (A) / `--profile b` (B) only;
  fake `XDG_CONFIG_HOME` (0700) in the scratchpad; hidden windows
  (`hyprctl dispatch exec "[workspace special:<name> silent] kitty …"`); one test per Slack account at a time; no
  mic/camera/screen capture; no sound; live waits ≤ ~10 min. The Windows VM `win11-dev` is shared: check it is free
  first (`virsh -c qemu:///system domstate win11-dev`, `tasklist` for others' builds), leave it as found, work in
  `%USERPROFILE%\ttyak-test`.
- User-visible words go through `tr`. Wiki pages (`docs/wiki/`) are updated in the task whose behaviour they describe;
  `python3 tools/wiki/check_links.py` exits 0 after each.
- PROGRESS.md: one row per task, ids **PT1, PT2, …** = task numbers, honest LIVE/UNIT/NOT, the commit hash.

## Review Focus

1. **An ACL call that fails on an unusual file system** (FAT, network share): the save must still succeed (debug log).
   Pinned in Task 1 by a test that makes `owner_only` fail (an injected error) and checks `write_private` still writes.
2. **A VIP override leaking past other rules**: a VIP's message in a muted channel, a "nothing"-level channel, or a
   plain channel message at "mentions" level must stay quiet even with the override on. Pinned in Task 5.
3. **A late bubble arriving after its conversation was read or superseded** must be closed, never left on screen.
   Pinned in Task 4.
4. **A hung toast-setting read** must not delay shows or hold ttyak's exit. Pinned in Task 3 (a fake slow setting).
5. **`publish.sh --wiki-dir` with leftovers** (untracked file, local commit, dirty edit) must never publish them.
   Pinned in Task 8.
