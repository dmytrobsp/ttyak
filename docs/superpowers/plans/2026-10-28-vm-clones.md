# VM clones Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An agent can get a throwaway Hyprland Linux VM or a throwaway Windows 11 evaluation VM — each a linked
clone of a frozen base — through the same `instance` commands and slots as the container desktops, run ttyak in it,
watch its windows and notifications, and have it gone afterwards; nothing appears on the maintainer's screen and
the maintainer's work VM is never touched.

**Architecture:** The claim tool (a private repository, named in `AGENTS.local.md`) gets a backend interface under
its `instance` commands: the existing podman code becomes one backend, user-mode libvirt (`qemu:///session`) the
other. The pool charges each desktop its own size. Bases are built by script into versioned folders
(`~/.local/share/<tool>/bases/<desktop>/<build>/`) with a `current` pointer; a clone is a transient libvirt domain
on a qcow2 overlay in `/dev/shm`, with the tool's metadata on the domain, a fresh NVRAM and TPM (Windows), reached
by ssh over vsock (Hyprland) or a localhost port (Windows) with the base's own key and pinned host key.

**Tech Stack:** Python 3.9+ stdlib (the claim tool); libvirt 10 / QEMU 8.2 in user mode, swtpm, OVMF, `qemu-img`,
`xorriso`, `socat`, `gpgv`; an Arch Linux cloud image with cloud-init, Hyprland, mako, kitty, PipeWire; Windows 11
Enterprise Evaluation with an `autounattend.xml`, Win32-OpenSSH, virtio-win drivers, the QEMU guest agent,
PowerShell 5.1.

**Spec:** [docs/superpowers/specs/2026-10-27-test-machines-design.md](../specs/2026-10-27-test-machines-design.md)
— Part 3, the spike of 2026-10-28, "VM clones — decided" and "VM clones — answers for the builder". The spike's
working files are in the private spike folder named in the task briefs (scripts, XML, the cloud-init seed, the
answer file, the setup script): reuse them, but nothing of the spike's that the answers rule out (fixed paths and
names, ports or MACs from the slot number, `StrictHostKeyChecking no`, plaintext passwords, logs on the SSD).

## Global Constraints

- Shell rules: bash, never fish (`NAME=value`); `set -euo pipefail`; no recursive `rm`/`chmod`/`chown`/`mv`/`cp` on a
  variable path (literal, or `${VAR:?}` after a check). The tool never `shutil.rmtree`s outside a path it checked
  is `<root>/tb-<safe id>` (clone folders) or `<bases>/<desktop>/<build>` (old bases), never follows a symlink there.
- The claim tool's rules hold (its README; Python 3.9 floor, stdlib only, tests pristine under `-W error`, its own
  git identity, implementers never push; nothing private in ttyak's tracked files — the tool is named only as "the
  claim tool named in `AGENTS.local.md`"). Lines at most 120 columns.
- **The maintainer's work VM**: the tool never writes to `qemu:///system`; the only system-URI calls are the
  existing read-only `domstate`/`dominfo` for the reserve. Every libvirt call of the VM backend names
  `qemu:///session` explicitly (one constant per use). Implementers never touch the shared Windows VM (named in
  `AGENTS.local.md`), its files or the system URI.
- **Nothing on the maintainer's screen; no capture.** No `<graphics>` element in any domain (no VNC, no SPICE); never
  start virt-viewer, virt-manager, remote-viewer or a QEMU with a gtk/sdl display. `virsh screenshot` is the only
  view. No host device but KVM and vsock reaches a VM; no audio backend but `none`.
- **SSD**: bases built once and rebuilt on command; clone overlays, NVRAM copies, console logs and domain XML live
  in `/dev/shm/<tool>-<uid>/tb-<id>/` (0700); libvirt's per-domain logs (`~/.cache/libvirt/qemu/log/<name>*.log`)
  are removed with the clone; nothing is compiled inside a VM.
- **Capacity**: sizes per desktop in `boxes.json` → `instances.sizes_gb`, defaults `sway 1.5, gnome 1.5,
  hyprland 2.5, windows 6.5` (guest RAM + QEMU overhead + the overlay cap; Windows' cap is 2 GB because a debug
  `ttyak.exe` is ~650 MB); overlay caps `instances.overlay_cap_gb` defaults `hyprland 0.5, windows 2`; a missing
  size falls back to `instance_gb`. FIFO stays strict.
- **Secrets**: each base's ssh private key and the Windows test user's password are made per build, owner-only
  (0600) beside the base, never printed, never in the repository, never mounted or copied into an instance.
  ssh always runs with the tool's own config (`-F`, `IdentitiesOnly=yes`, `IdentityAgent=none`, `BatchMode=yes`,
  `UserKnownHostsFile=<base>/known_hosts`, `HostKeyAlias=tb-<desktop>-<build>`), never the user's `~/.ssh`.
- **Downloads** go to `~/.local/share/<tool>/dl/` with checksums checked before use (the Arch image: its SHA-256
  and `gpgv` against a key file pinned in the repository; pinned SHA-256s for OpenSSH, virtio-win and the guest
  agent; the Windows ISO: no published checksum — its size and its `install.wim` edition are checked). Downloading
  happens only in `instance base build` (and `--download` for the ISO), never in `new`.
- Exit codes as the claim tool's: 0, 2 (usage; no base built — with the build command), 3, 5 (podman, libvirt,
  QEMU, swtpm, the firmware, socat or xorriso missing; a start that failed), 6 (no live slot claim), 10, 130.
- Implementers never run ttyak against Slack and never use the Slack test accounts; ttyak's live checks are the
  controller's (Task 7). Real VMs in tests are opt-in (`<TOOL>_VM=1`), started only when `free` leaves the reserve,
  and removed by the test by name.

## Review Focus

1. **A VM that is not ours** — the work VM in `qemu:///system`, a session domain without the tool's metadata, one of
   another pool — is never listed, stopped or removed (Task 3, `test_never_writes_system_uri`,
   `test_reap_ignores_foreign_domains`).
2. **Leftovers after a crash or a host reboot**: a clone folder without a domain, a domain without a live claim,
   libvirt's per-domain logs — all removed by `reap` (Task 3, `test_reap_sweeps_orphan_clone_folders`,
   `test_rm_removes_libvirt_logs`).
3. **A base rebuilt while clones run on it**: the running clones keep their backing file; the old build is removed
   only when no clone uses it (Task 3, `test_gc_keeps_base_in_use`, `test_build_never_writes_current_build`).
4. **Memory**: a Windows request with less than its size free waits, and holds up a sway request behind it; two
   `new` at once never both get the last room (Task 2, `test_sized_grants_respect_capacity_concurrently`,
   `test_big_head_blocks_small_behind`).
5. **`/dev/shm` filling up**: `new` refuses when the tmpfs lacks the overlay cap plus a margin; a renewal removes a
   clone whose overlay passed its cap (Task 3, `test_new_refuses_when_shm_short`,
   `test_renew_removes_clone_over_cap`).

### Task 1: A backend interface under `instance` (refactor)

**Files (claim tool):** Create `<tool>/backends.py` (the interface and the registry), `<tool>/podman_backend.py`
(moved from `instances.py`); modify `<tool>/instances.py`, `<tool>/cli.py`; tests: the existing ones, unchanged
in what they assert (only import paths and patch targets may move).

**Interfaces:**
- Produces `backends.Backend` (a class with these methods; `podman_backend.Podman` implements them):
  `name: str`, `desktops: tuple`, `check() -> None` (raises `backends.Missing` → exit 5),
  `list(pool_id: str) -> list[dict]` (`{name, desktop, claim, slot, holder, purpose, created, state, backend}`;
  only this tool's instances of that pool), `start(ctx: StartContext) -> None` (raises `backends.StartFailed(reason)`;
  the caller undoes through `remove`), `remove(name: str, claim: str) -> bool` (only an instance of that claim),
  `ready_env(name) -> dict`, `exec_argv(name, env, cmd: list, tty: bool) -> list`,
  `capture(name, cmd: list, timeout: float) -> tuple[int, bytes, bytes]`.
- `backends.for_desktop(desktop) -> Backend`; `backends.all() -> list[Backend]`.
- `StartContext` (a dataclass): `name, claim, slot, holder, purpose, desktop, home, mounts, renew: Callable`.
- The per-desktop commands (`shot`, `notifications`, `windows`, `record`) dispatch through a table
  `instances.OPS[desktop][command]`; an unknown or unsupported pair exits 2 as today.
- `reap` and `ls` ask every backend; a backend whose `check()` or `list()` fails is reported on stderr and skipped,
  the others still reaped. `new` calls only the chosen backend's `check()`.

### Task 2: Slots sized per desktop

**Files (claim tool):** Modify `<tool>/slots.py`, `<tool>/instances.py` (the ticket and the resume line carry the
desktop), `<tool>/cli.py` (`slot status`), `README.md` ("Slots"); test `tests/test_slots.py`.

**Interfaces:**
- `slots.size_bytes(cfg, desktop) -> int` (`sizes_gb[desktop]`, else `instance_gb`).
- `slots.claim(..., desktop: str = "sway", charges_fn: Optional[Callable[[], dict]] = None)`: the held record and
  the queued ticket store `desktop` and `size`; a record without them (an older pool file) counts as
  `instance_gb`. `charges_fn` (called before the mutex, like `vms_fn`) returns `{claim_id: bytes}` — what a started

  `max_slots` held. Replaces `allowed()` in `claim`; `ram_figures` reports the sizes, the charges and "room now
  (GB)" instead of an `allowed` count (`slot status` and its `--json`).
- The head of the queue alone may be granted (strict FIFO, as today).

### Task 3: The libvirt backend and the bases folder

**Files (claim tool):** Create `<tool>/bases.py`, `<tool>/libvirt_backend.py`, `<tool>/vmxml.py`,
`tests/fake_virsh.py`, `tests/fake_qemu_img.py`, `tests/test_bases.py`, `tests/test_libvirt.py`; modify
`<tool>/instances.py` (registry, `rm`, the overlay check on renew), `<tool>/config.py`, `README.md` (a section
"VM instances", the wording fixes of the design's answers).

**Interfaces:**
- `bases.root() -> str` (`~/.local/share/<tool>/bases`); `bases.current(desktop) -> Base` (raises
  `bases.NoBase(desktop)` → exit 2 with "build it: <tool> instance base build DESKTOP"); `Base`: `desktop, build,
  path (the folder), disk, key, known_hosts, alias, meta: dict` (`built`, `expires` or None, `guest_uid`,
  `ssh_user`, `memory_mib`, `vcpus`, `firmware: "bios"|"uefi"`, `transport: "vsock"|"tcp"`, `sources`);
  `bases.new_build(desktop) -> str` (a fresh folder; never the current one); `bases.publish(desktop, build)`
  (atomic `current` switch); `bases.gc(desktop, in_use: set) -> list` (removes builds that are neither current nor
  in use, under the base lock); `bases.build_lock(desktop)` and `bases.base_lock(desktop)` (context managers;
  flock files beside the builds); `bases.warnings(base, now) -> list[str]` (Hyprland: older than 30 days; Windows:
  under 14 days left) and `bases.expired(base, now) -> bool` (Windows: under 1 day left → `new` exits 2).
- `vmxml.domain(base, name, clone_dir, meta: dict, mac: str, mounts: list) -> str`: `kvm`, q35,
  `host-passthrough`, `base.meta` memory and vCPUs; the overlay as a virtio disk; `<interface type='user'>`
  (Hyprland) or QEMU's own SLIRP with `hostfwd=tcp:127.0.0.1:0-:22` through `<qemu:commandline>` and an explicit
  PCI address (Windows); `<vsock>` with `cid auto` (Hyprland); UEFI Secure Boot from the configured firmware
  paths, the per-clone NVRAM copy and a `<tpm>` emulator (Windows); the serial console logged into the clone
  folder; virtio video, no `<graphics>`; `<sound model='ich9'>` with `<audio type='none'>` (Windows); virtio rng,
  memballoon; 9p `<filesystem>` read-only per mount and read-write for the home (Hyprland); the tool's metadata
  element (namespace `https://<tool>.invalid/instance`: pool, claim, desktop, slot, holder, purpose, created,
  base build).
- `libvirt_backend.Libvirt(Backend)` with desktops from the kinds registered by Tasks 4–5; `<TOOL>_VIRSH_BIN`,
  `<TOOL>_QEMU_IMG_BIN`, `<TOOL>_SSH_BIN` override the programs. `start`: base lock → `bases.current` → refuse
  when expired → check `/dev/shm` free ≥ overlay cap + 1 GiB → clone folder (0700) → overlay
  (`qemu-img create -f qcow2 -b <disk> -F qcow2`) → NVRAM copy → `virsh -c qemu:///session create <xml>` → read
  back the vsock CID or the forwarded port (`virsh qemu-monitor-command --hmp 'info usernet'`) into the clone
  folder → the kind's ready wait (its own timeout). `remove`: `virsh destroy` only a domain whose metadata names
  this claim and pool, then the clone folder (checked path), then the libvirt logs of that name. `list`: session
  domains with our metadata and pool, plus clone folders without a domain (state `orphan`, so `reap` sweeps them).
- `libvirt_backend.ssh_argv(clone, base, cmd: list, tty=False) -> list` — the ssh command with the tool's config
  (the Global Constraints' options; vsock through `socat - VSOCK-CONNECT:<cid>:22` as ProxyCommand).
- Renewals (`_enforce`'s renew hook) of a VM check the overlay's size; past its cap the clone is removed and the
  command exits 5 ("overlay over its cap").
- `charges_fn` for Task 2: for each started VM of the pool, `max(0, size − (qemu RSS + overlay bytes))`, RSS from
  `virsh dommemstat` (`rss`).
- Kinds register with `libvirt_backend.register(Kind(desktop, ready: Callable, ready_timeout: float, ops: dict))`;
  this task registers a test-only kind for the fakes.

### Task 6: Working in a Windows clone

**Files (claim tool):** Create `vms/windows/helper.ps1` (baked into the base by Task 5's build, which this task
extends); modify `<tool>/vm_windows.py`, `<tool>/instances.py`, `<tool>/cli.py`, `README.md`; test
`tests/test_vm_windows.py`.

**Interfaces:**
- `instance exec NAME ID [--] CMD...` on Windows: through ssh to cmd.exe (session 0: files, `ttyak ctl`); `exec
  --desktop` runs CMD in the logged-on user's session through `helper.ps1` (a scheduled task with Interactive logon,
  stdout, stderr and the exit code back through files under `C:\<tool>\run\<n>\`; the task's execution time limit
  is `--timeout DUR`, default 25m), and returns its exit code.
- `instance push NAME ID SRC DST` / `instance pull NAME ID SRC DST` (scp with the tool's ssh options; on Hyprland
  too). The source of `push` passes the existing source checks (never the maintainer's real ttyak folders).
- `shot` on Windows: `virsh screenshot` into the clone folder, then `_write_private`. `windows`: `helper.ps1
  windows` in the session (title, process, focused) in the same output format as the other desktops.
  `notifications`: the toast history of an app id given with `--app` (default: ttyak's, taken from ttyak's code by
  the implementer and written in the README) through `helper.ps1`, same format. `record` and `--home`/`--mount` on
  Windows: exit 2 with the reason.
