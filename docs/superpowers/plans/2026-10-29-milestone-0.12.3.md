# Milestone 0.12.3 — plan

The first real run (the trial) of [Running a milestone](../../agents/workflow.md#running-a-milestone). Five small units
from [milestone 0.12.3](https://github.com/dmytrobsp/ttyak/milestone/4), the maintainer's pick (2026-10-29). Ledger:
[2026-10-29-milestone-0.12.3.md](../ledgers/2026-10-29-milestone-0.12.3.md). Scratch (rules file, briefs, reports,
evidence, agent ids): `.superpowers/sdd/2026-10-29-milestone-0.12.3/` in the main checkout, git-ignored.

Milestone branch `milestone/0.12.3`; unit branches `m/0.12.3/<unit>`; worktrees under the helper's default root.

## Global Constraints (every brief quotes them)

- The hard rules of [AGENTS.md](../../../AGENTS.md); the shell rules always: bash (`NAME=value`, never fish's `set`),
  `set -euo pipefail` at the top of every multi-command script, never a recursive `rm`/`chmod`/`chown`/`mv`/`cp` (or
  `find -delete`) on a path built from a variable — a literal path, or `${VAR:?}` after checking it.
- Never run `tools/milestone/milestone.py`; never `git push` (any form). The controller pushes and opens pull
  requests.
- Work only in the unit's worktree and the plan's scratch folder (plus what a live-check recipe makes and removes).
  Never `cargo fmt`; never `target/release`; never the maintainer's real ttyak folders; never a profile not given.
- Files that quote guarded commands (reports, scripts) are written with the Write/Edit tools, never a Bash heredoc.
- TDD with the RED shown (by mutation if the code already behaves); the whole `cargo test` in the worktree before every
  commit; one commit per step, explicit paths, `Fixes #N` in the unit's last commit, the co-author trailer.
- Live checks only by [Live checks in a milestone](../../agents/live-testing.md#live-checks-in-a-milestone): instances
  only, per-unit fake home `<scratch>/<unit>-home`, evidence files in `<scratch>/<unit>/`, accounts claimed first.
- Public wording in commits and code: no account, workspace, host or person names, no ids or emails.
- A refusal: stop, `git status`, report the command exactly and the refusal text verbatim; never reword or retry.

### `redirects` — #51

- A custom `reqwest::redirect::Policy` shared by the three slack-core clients (`api.rs`, `session.rs`, `signin.rs`):
  a 307 or 308 (which re-send the body) is followed only to Slack's own hosts (`slack.com`, `slack-gov.com` and their
  subdomains; the implementer checks which other Slack hosts the code calls); 301/302/303 stay followed as now (reqwest
  turns them into a body-less GET), so avatar, file and gravatar redirects keep working; the same hop limit as the
  default. The updater's client (`crates/ttyak/src/update.rs`, GETs only) is unchanged.
- Tests: the policy's decision as a pure function (host and status cases), and if practical a local test server that
  answers 307 to another host and records whether the body arrived.

### `mouse` — #47

- `parse_cb` decodes buttons 10 and 11 (`Cb` 130/131, +32 for a drag) as their own `MouseButton` variants; ttyak
  ignores them (an explicit no-op arm where it matches on side buttons, if any match needs it). Parser tests for
  down, drag and release of both. `vendor/crossterm/TTYAK-PATCH.md` updated; every changed line marked `// ttyak:`.
  The Keys wiki page gets at most a short note that 10 and 11 do nothing.

### `unread` — #56

- On opening a conversation whose read mark (`new_since`) is older than the oldest loaded message while more history
  exists, ttyak pages back (the seek paging of `event_loop.rs`) until a message at or before the read mark is loaded,
  at most 5 more pages; the "— new —" line then sits above the first unread message and the jump to it works as now.
  Past the cap, a translatable note at the top of the loaded part says more new messages are above.
- Unit tests: more than 50 unread (the paging stops at the read mark), more than the cap (the note), the read mark
  inside the first page (no extra request).
- Live: A in an instance (sway), B posts 60 messages to A's DM after A has read it, A opens the DM: the line sits above
  B's first message. Evidence per live-testing.md.

### `pages` — #41

- `timeout-minutes` on both jobs and on the network steps (the release fetch, the artifact upload, the deploy), in the
  style of the other workflows. Checked with `actionlint` if installed, else a YAML parse; CI's own run on the pull
  request. The real exercise is the Pages run the final merge into `master` starts.

### `huddles` — #50 + #36 (after `unread` merges: both touch `event_loop.rs`)

- "1 h" when the minutes are 0: a new translatable string `{h} h`, the old one kept for the other case.
- An unknown conversation in the view: one `conversations.info` per id, cached; `#name` for a public channel, else
  "a conversation you are not in" (translatable).
- The start notice: a `huddle_start` refetch must not mark a huddle as known before its `sh_room_join` is handled; a
  unit test for the order start → refetch answer → join.
- #36: the short audio line's words go through `tr()` and into `WORDS`.

## Each unit

As [A unit, from brief to merge](../../agents/workflow.md#a-unit-from-brief-to-merge): brief (Write tool) → background
implementer → privacy check on copies → push and pull request → review, fix rounds to the same implementer, scoped
re-reviews by the same reviewer → gate (head, CI green, `gate`, the whole `cargo test`, push) → `rm`.

## The end

[The end of a milestone](../../agents/workflow.md#the-end-of-a-milestone): the final whole-milestone review (opus) and
one fix wave; the whole `cargo test`, the Windows cross-build and `cargo test --no-run` for Windows; CI on the
milestone pull request; the controller's live smoke check of the milestone branch in an instance; the milestone pull
request with the report ([milestone-report.md](../../agents/milestone-report.md)); the maintainer's "merge"; the
retro in the ledger and the doc changes it calls for. A release only on the maintainer's word.
