# macOS VM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An agent on the desktop can get a throwaway macOS VM on the Mac — a Tart clone of a frozen base built from
Apple's restore image — through the same `instance` commands as the other desktops, run ttyak in it with a claimed
account's session, see its windows, notifications and screen, and have it gone afterwards; nothing appears on the
Mac's screen, nothing touches its microphone, and the Mac keeps a 6 GB reserve for the maintainer.

**Architecture:** The claim tool (a private repository, named in `AGENTS.local.md`; `<tool>` below, its folders
`~/.<tool>/…`, its variables `<TOOL>_…`, its Python package `<pkg>/`) gets: a memory reader and per-host pool
settings for macOS (Task 1); a relay that forwards `instance` commands for desktops a box hosts from the desktop to
that box's tool over ssh (Task 2); a
Tart backend on the Mac — clones, a keeper process per VM, ownership records, ready, `exec`, mounts (Task 3); the
macOS desktop commands — `exec --desktop`, `shot` through a small VNC client, `windows`, `notifications` (Task 4);
the base build on the Mac and the real tests (Task 5); ttyak's docs and the live check (Task 6).

**Tech Stack:** Python 3.9 stdlib on both hosts (the Mac's `/usr/bin/python3`); Tart 2.41 (pinned release bundle);
Packer with the tart plugin (pinned) for the Setup Assistant keystrokes; Apple's `/usr/bin/ssh`, `curl`, `caffeinate`,
`vm_stat`, `sysctl`, `pmset`, `lsappinfo`, `log`; macOS 26 in the guest.

**Spec:** [docs/superpowers/specs/2026-10-27-test-machines-design.md](../specs/2026-10-27-test-machines-design.md)

## Global Constraints

- Shell rules: bash on the desktop, never fish (`NAME=value`); `set -euo pipefail`; no recursive `rm`/`chmod`/`mv`/`cp`
  on a variable path (literal, or `${VAR:?}` after a check); on the Mac, VMs are removed with `tart delete NAME`,
  never `rm -rf` of a VM folder.
- The claim tool's rules hold (its README; Python 3.9 stdlib on both hosts, tests pristine under `-W error`, its own
  git identity, implementers never push, lines ≤ 120). The macOS modules import on Linux; desktop tests use fakes.
- **Nothing private in ttyak's tracked files**: never the claim tool's name, its folders or variables (AGENTS.md,
  "Public wording"): `<tool>`, `~/.<tool>/…`, `<TOOL>_…` only.
- **The Mac is a shared box**: every command on it goes through the box tool under a live box claim (`claim mac`,
  `run`/`push`/`pull`, `release`), never plain ssh; implementers update the Mac's clone with `git pull` under a claim
  before real tests. The maintainer's own files, apps, settings and `~/.tart` are never touched.
- **Nothing on the Mac's screen; no capture**: every Tart run has `--no-graphics --no-audio --no-clipboard`, VNC on
  127.0.0.1 only with `CI=true`; never a VNC viewer, never a screenshot of the Mac's own screen; no sudo on either
  host; no launchd job in the maintainer's account.
- **Capacity on the Mac**: `instances.hosts.mac`: reserve 6 GB (the maintainer), `max_slots` 1, `macos` 4.5 GB; no
  grant under memory pressure; refused on battery (exit 5).
- **Secrets**: the base's ssh key and the guest user's password are made per build, 0600, never printed, never in a
  repository; Slack sessions reach a VM only by `push` of an `install`ed copy; nothing of the tool's folders is ever
  mounted or pushed.
- Exit codes as the tool's: 0, 2, 3, 4 (box withdrawn), 5 (unreachable, a program missing, a start that failed, on
  battery), 6, 10, 130.
- Implementers never run ttyak against Slack and never use the Slack accounts; ttyak's live check is the
  controller's (Task 6).

## Review Focus

1. **A desktop agent killed mid-`new`**: the Mac leaves the queue, removes the VM and releases the slot (Task 2,
   `test_relay_eof_runs_cleanup`).
2. **A VM that is not ours** (the maintainer's own Tart VMs in `~/.tart`, another pool's) is never listed, stopped or
   deleted (Task 3, `test_never_touches_foreign_tart_vms`).
3. **The Mac short of memory or on battery**: a request waits (memory) or is refused (battery, pressure); the reserve
   holds (Task 1, `test_darwin_available_and_reserve`; Task 3, `test_refused_on_battery`).
4. **A dead VM's holder reaching another VM**: commands check the record, the running VM and the keeper first (Task 3,
   `test_exec_refuses_when_vm_gone`).
5. **Pull writing outside DST**: a tar stream with links, `..` or absolute names is refused (Task 2,
   `test_pull_rejects_unsafe_tar`).

**Files (claim tool):** Modify `<pkg>/slots.py`, `<pkg>/config.py`, `README.md` ("Slots"); test
`tests/test_slots.py`.

**Interfaces:**
- `config.instances(host=None)` merges `instances.hosts.<self name>` over the global settings (the Mac:
  `reserve_gb 6`, `max_slots 1`, `sizes_gb.macos 4.5`).
- `slots.read_meminfo()` on Darwin returns `MemTotal` (`sysctl -n hw.memsize`) and `MemAvailable` (from `vm_stat`:
  total − (internal − purgeable + wired + compressed) pages × page size) and `Pressure` (`sysctl -n

  not the libvirt host of a box VM.

### Task 2: The relay from the desktop to the Mac

**Files (claim tool):** Create `<pkg>/relay.py`, `tests/fake_mac_hop.py`, `tests/test_relay.py`; modify
`<pkg>/instances.py`, `<pkg>/cli.py`, `boxes.json` (the Mac: `"desktops": ["macos"]`), `README.md`.

**Interfaces:**
- A box entry may list `desktops`. `instance new --desktop D` for a hosted desktop makes the ticket `BOX-<hex>` and
  relays; every instance command whose NAME/ID starts with a box name relays to that box; a local ticket may not
  start with a box name.
- `relay.run(box, argv, stdin=None) -> int`: `ssh -T` with `ServerAliveInterval`, the box's `remote` plus
  `instance … --relay <version>`; the remote side answers with JSON lines (`resume`, `rm`, `out`, `err`, `exit`);
  the desktop renders `resume:`/`rm:` lines for its own argv and shell. An outdated remote: exit 2 "git pull on the
  BOX". ssh's own 255 → exit 5 "BOX unreachable"; the remote maps an inner 255 to 5.
- On the remote, a relay watcher: stdin closed → `interrupt_main()` → the existing Ctrl-C cleanup.
- `push`: the desktop checks the source, sends a tar stream; `pull`: the remote sends a tar stream, the desktop
  extracts regular files and folders only (no links, no `..`, no absolute names), owner-only; `shot`: PNG bytes back,
  written 0600. `ls` adds each hosting box's rows, or "BOX unreachable".
- A withdrawn box refuses new hosted instances (exit 4).

- [ ] **Step 1: Failing tests** with the fake hop (a local tool run as the box with its own folders):
  `test_relay_new_and_resume_lines`, `test_relay_eof_runs_cleanup`, `test_relay_exit_codes`,
  `test_pull_rejects_unsafe_tar`, `test_push_source_checked_on_desktop`, `test_routing_by_prefix`,
  `test_withdrawn_box_refuses_new`, `test_outdated_remote_refused`. Show them RED.
- [ ] **Step 2:** Implement. **Step 3:** whole suite (+ real podman if idle); commit `instances: relay to a box that
  hosts desktops`.

### Task 3: The Tart backend on the Mac

**Files (claim tool):** Create `<pkg>/tart_backend.py`, `<pkg>/vm_macos.py` (the kind), `vms/macos/pins.json`,
`tests/fake_tart.py`, `tests/test_tart.py`; modify `<pkg>/backends.py` (registry), `README.md`.

**Interfaces:**
- `instance tart install`: Tart's release bundle by `/usr/bin/curl`, SHA-256 from `pins.json`, kept whole under
  `~/.<tool>/bin/`; `<TOOL>_TART_BIN` overrides. `TART_HOME=~/.<tool>/tart`; auto-prune off.
- `Tart(Backend)`: `start` — refuse on battery (`pmset -g batt`), clone `tb-<id>` from `base-macos-<build>`, write the
  record `~/.<tool>/macos/tb-<id>/clone.json` (pool, claim, slot, holder, purpose, created, build), snapshot each
  `--mount SRC:NAME` with `cp -c` into the record folder, start the keeper; `list` — our `TART_HOME`'s `tb-*` with
  records of this pool; `remove` — `tart stop` + `tart delete` + the record folder, only for that claim; `ready` — the
  guest's ready file over ssh (90 s); `exec` — Apple's `/usr/bin/ssh` with the base's key, pinned host key
  (`HostKeyAlias tb-macos-<build>`), `sh -c`, the IP from `tart ip`.
- The keeper (`instance _keep NAME`, a new session): `caffeinate -s -i tart run NAME --no-graphics --no-audio
  --no-clipboard --vnc-experimental [--dir NAME:PATH:ro]…` with `CI=true`; records PIDs and the VNC address (0600);
  every minute stops and deletes the VM when its slot claim is not live; exits when the VM is gone.
- Before every ssh: the record, `tart list` (running) and the keeper's PID; otherwise exit 5 "not running".
- Apple's two-VM limit → `StartFailed("macOS allows two VMs at once; another is running")`.
- `base ls|gc` generalised per backend (bases on the Mac: only the current build kept).

- [ ] **Step 1: Failing tests** with `fake_tart`, `fake_caffeinate`, a fake `pmset` and ssh:
  `test_never_touches_foreign_tart_vms`, `test_refused_on_battery`, `test_exec_refuses_when_vm_gone`,
  `test_keeper_removes_vm_when_claim_lapses`, `test_mount_snapshot_and_readonly_share`, `test_tart_flags_always_set`,
  `test_two_vm_limit_message`, `test_install_checks_pin`. Show them RED.
- [ ] **Step 2:** Implement. **Step 3:** whole suite; commit `instances: a Tart backend for macOS VMs`.
