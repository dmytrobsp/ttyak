# ttyak 0.12.2 — design (2026-10-26)

Milestone 0.12.2 (https://github.com/dmytrobsp/ttyak/milestone/3), scoped by the user on 2026-10-26: the Windows
hardening found during the README/wiki work, the in-app help matching the code (#31), VIPs in ttyak's own
notifications (#32), notification leftovers (#15, #17), `tools/wiki/publish.sh` with a reused `--wiki-dir` (#33) and
the 0.11.0 leftovers (#28). All fixes; no new features beyond one F6 row. Ends with a 0.12.2 release (the tag only with
the user's word).

The facts behind this design were gathered read-only on 2026-10-26 (a code survey of every item, and a study of what
Slack's own client does for VIPs: its help center and its client code). Line numbers in the plan are as of 26d37e3.

## 1. Windows: private files owner-only (hardening)

On Linux and macOS ttyak writes its private files 0600 (folders 0700). On Windows they inherit the folder's ACL. Fix:
on Windows, the same files get a protected DACL that grants only **the current user (TokenUser SID), SYSTEM and
Administrators** — the convention Win32-OpenSSH uses for private keys (my call: SYSTEM and Administrators can read
the profile anyway, and backup tools keep working).

- A helper in slack-core (`owner_only(path, dir)`), a no-op off Windows; `windows-sys` (already in Cargo.lock) gains
  the security features slack-core needs.
- Applied to: `session::write_private` (session.json, the drafts file, the update-check state — on the temp file
  before writing, so the rename keeps the DACL), `status_file::write_to` (its file and the folder it creates), and
  the temporary cookie-database copies in `login_import` (they hold cookies).
- If the file system can't hold ACLs (FAT/exFAT, some network shares): log at debug and go on (my call: losing a
  sign-in over this would be worse).
- On Windows the status file ignores `XDG_RUNTIME_DIR` (an MSYS/Cygwin shell may set it to a shared folder) and stays
  in the cache folder (my call).
- Verified by Windows-only tests that read the DACL back, run on the Windows VM (CI only cross-builds Windows).

## 2. Windows uninstall: only regular files are removed as old copies (hardening)

`ttyak uninstall` on Windows removes old copies of the program (`ttyak.old*.exe`) and, when one is in use, hands it to
a delayed `del`. A directory or a link with such a name must never be handed over. Fix: the plan lists only regular
files (`DirEntry::file_type`, which doesn't follow links), and the delayed-delete fallback also requires a regular
file; anything else falls to the plain "could not delete" path. `update::remove_old_copies` gets the same filter.

## 3. In-app help matches the code (#31)

Every mismatch listed in #31 is fixed in the help text (F6 help, F1 Commands and the composer's command table, the
huddle view's audio line, `share_screen`'s description and `ctl --share-screen`'s doc), with the wording the wiki
already uses. Terminal names without versions (my call: the probe decides, versions age). The VIP sentence follows §4.
User translations keyed by an old English string are orphaned — accepted. Where a fact comes from a constant (`/dm`'s
`MAX_GROUP`), the help formats the constant in, and a test pins the two command tables agreeing.

## 4. VIPs, the way Slack does them (#32)

What Slack's client does (help center: "Add contacts as VIPs", "Pause your Slack notifications"; its client code):
being a VIP **never** makes a message notify that otherwise wouldn't. The one effect on notifications: when
**"Always allow notifications from VIPs"** (user pref `priority_dnd_override`, off by default) is on, a message that
would notify but is held back **only because notifications are paused** (snooze, notification schedule) is let
through, if the sender (or a bot's `bot_profile.user_id`) is in `vip_users` **and** the conversation is a DM or group
DM or the message has a user, user-group or channel mention (`@here`/`@channel`/`@everyone` don't count; the mention
needn't be of you). The feature needs a paid plan (`team.plan` non-empty in `client.userBoot`).

ttyak follows exactly that:
- `attention::decide` is unchanged. The pause gate in `attention::outputs` lets a note through when it carries the
  VIP override (computed where the note is made, from the workspace's `vip`, `priority_dnd_override`, paid plan, the
  conversation kind and the message's mentions).
- Applies to the shown workspace and the hidden workspaces' watcher alike (their prefs come from `client.userBoot` —
  verified read-only on the test workspace before relying on it), and follows live `pref_change` events.
- Not changed (my calls): huddle starts and invitation rings (Slack's rule is for messages); the system's own
  do-not-disturb (an OS setting, not Slack's pause); the VIP sound, the "VIP unreads" sidebar section and Activity's
  VIP filter (separate features, not in this milestone).
- **F6 → Notifications gets a row "Always allow notifications from VIPs"** (the user's decision), kept on Slack
  (`users.prefs.set priority_dnd_override`), next to the VIP list; its help says the rule above. On a free plan the row
  says it needs a paid plan.

## 5. Notification leftovers (#15, #17)

- **A late bubble is tracked** (my call): when the notification server answers after ttyak's wait, the bubble is still
  recorded, so it is replaced, withdrawn or closed like any other; one superseded or read meanwhile is closed when it
  arrives.
- **A huddle-start bubble goes when the huddle ends** (the user's decision), and when the invitation is cancelled
  (e.g. you joined elsewhere) — in the shown workspace and in hidden ones. The status line's "missed X's huddle" stays.
- **Windows: the toast setting is read off the show path** (#17): shows no longer wait for `toast::setting()`; the
  setting is read on a detached thread, cached and refreshed, and used by the shown-log line and F6's route. ttyak's
  exit can't be held by a hung toast call (the runtime shuts down with a timeout).
- **Windows Terminal older than 1.14** (full-screen ttyak held back as busy): documented as not supported (my call:
  Windows Terminal updates itself; 1.14 is from 2022) in the wiki's Notifications page and its Troubleshooting entry.

## 6. `tools/wiki/publish.sh` with a reused `--wiki-dir` (#33)

A reused clone is the script's own cache (my call: reset, not refuse): after the origin check it is fetched, reset hard
to the wiki's branch and cleaned (`git clean -fdx`), so leftovers and local commits never reach the wiki. With `--push`
it pushes whenever the clone is ahead of the remote, so a dry run followed by `--push` works. Path checks compare by
identity (`os.path.samefile`), not spelling, so case-insensitive file systems can't slip past. The usage text and
`docs/RELEASING.md` step 7 (which still quotes the site's old winget sentence) are corrected.

## Constraints

As every ttyak plan: small verified steps, one commit each; TDD for code; never the `test` profile (the user's work
workspace) — live checks on the test workspace only, one account per test at a time, hidden windows; no `cargo fmt`,
no `target/release`; Windows-only checks on the shared Windows VM (check it's free first); public wording in commits
and issues; LIVE/UNIT/NOT honesty in PROGRESS.

## Calls made without the user (for review)

ACL accounts (user + SYSTEM + Administrators); ACL failures logged, not fatal; status file ignores `XDG_RUNTIME_DIR` on
Windows; cookie copies included; help names terminals without versions; VIP override not applied to huddles, system
DND or sounds; late bubbles tracked; huddle bubbles also withdrawn on a cancelled invitation; Windows Terminal < 1.14
documented as unsupported; reused `--wiki-dir` reset rather than refused; #28's Arch screen checked live in a container.
