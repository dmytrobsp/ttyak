# Ledger — plan docs/superpowers/plans/2026-10-28-vm-clones.md

Design: docs/superpowers/specs/2026-10-27-test-machines-design.md (Part 3; the spike of 2026-10-28, "VM clones —
decided", "VM clones — answers for the builder"). Start: ttyak 0ee9cab, the claim tool e79a81a. Tasks: 1 a backend
interface, 2 sized slots, 3 the libvirt backend and bases, 4 the Hyprland VM, 5 the Windows evaluation base, 6
working in a Windows clone, 7 ttyak's live checks in the VMs, final review. Tasks 1–6 are in the claim tool's
private repository.

## Pre-flight scan

| Rows | Produces → consumes | Found |
|---|---|---|
| 1 → 3 | `Backend`, `StartContext`, `OPS` → the libvirt backend | agree |
| 2 ↔ 3 | `claim(desktop, charges_fn)` ← the VMs' charges | agree |
| 3 → 4, 5 | `bases.*`, `Kind`, `ssh_argv`, `vmxml.domain` → the kinds | agree |
| 5 → 6 | the base build → `helper.ps1` baked in (Task 6 extends the build and rebuilds) | agree |
| 4, 6 → 7 | `exec`, `push`, `notifications`, `windows`, `shot` → ttyak's recipe | agree |

- Ruling: the Windows slot is 6.5 GB, not the design's "about 5 GB" — a debug `ttyak.exe` is ~650 MB, so the
  overlay cap is 2 GB (4 GiB guest + ~0.5 overhead + 2) — costs one fewer Windows clone at a time if wrong.
- Ruling: Task 7 step 2 (live, with the Slack accounts) is the controller's; implementers never run ttyak against
  Slack — costs time if wrong.
